# lucid — PRD и устройство игры

Единая точка входа в lucid — что это, как работает игра, как устроена, где что лежит, что открыто. Перед задачей по lucid читай этот документ; меняешь поведение — правь его в том же коммите.

Актуально на 2026-09-23, ветка `feat/lucid`, в `master` не влита.

Пути 1–5 — от `server/src/games/lucid/`, если не указано иное; `shared/` = `tools/shared/src/games/lucid/types/`. Раздел 6 — от `client/src/`.

## 1. Продукт

**Что это.** Онлайн-бродилка для компании друзей, 2–6 игроков; тему, события и оформление каждой партии генерирует нейросеть, механика одна для всех тем.

**Цель.** Первым дойти до Финиша. Один вечер, 30–40 минут, доигрывания нет.

**Принципы:** нейросеть генерирует содержание, не механику (ADR-0001); сервер авторитетен, клиент шлёт только намерения (ADR-0002); эффект собирается из атомов с целью и условием, не выбирается из перечня (ADR-0003); сначала доступ по ссылке без учёток, под публичность уже заложены id игрока, учёт стоимости генерации, хранение темы (ADR-0005).

**Не-цели:** не realtime-adventure; без накопительной экономики и банкротства (один Ресурс); без подготовки к нагрузке заранее (партия — килобайты). Без аналитики (PostHog недоступен в РФ, свой учёт токенов). Расширяемость (новый атом/клетка/карта без переписывания движка) заложена сразу.

**Первая версия.** Входит: лобби 2–6 по ссылке; мир и события нейросетью, скелет трека кодом; тема от игроков, жеребьёвка кубиком; трек с развилками, кубик, движение, Ресурс, Выборы с порогами; поле SVG в палитре темы; запасная партия при сбое генерации.

Отложено сознательно — проверяем интерес к партии без этого: карточный слой целиком, Слепки партий, порталы, капканы, цветные клетки-якоря; отсюда же 4 атома/цели в первой версии вместо более широкого словаря ADR-0003 — не дефект, а рез.

Решение заказчика 2026-09-23 по недоделанному (`docs/lucid/OPEN-QUESTIONS.md`): персонажи в честь игроков — сделано как простая роль у каждого игрока (3, 4.3, 5.5, 6.3); «скелет кодом» — не будет, выбор оставили за моделью, договорились мерить.

## 2. Путь игрока

1. **Ник.** Анонимный id при первом заходе, живёт в браузере; место в партии закреплено за id, не за соединением (`room/Party.ts:99-112`).
2. **Вход.** Только по ссылке, списка комнат нет. `/lucid/lobby` создаёт партию, `/lucid` принимает по `partyId+playerId+nickname`.
3. **Тема.** Каждый предлагает (≤200 символов) или отказывается — оба варианта считаются готовностью, видно всем до розыгрыша.
4. **Запуск.** Только владелец, от 2 игроков (`Party.ts:94-96`). Кубик выбирает тему среди предложенных по сиду партии, иначе — из 5 подсказок.
5. **Ожидание генерации.** «Мир» сразу, затем трек и события одним сообщением (4.2). Потолок 180 с (`init.ts:24`), дальше — запасная партия, честно в ленте.
6. **Ход.** Бросок доступен только `ctx.currentPlayer`, у остальных кнопки выключены; таймера хода нет.
7. **Событие и выбор.** Доступный по цене вариант — полноэкранная карточка (сворачиваемая, не закрываемая), ≤3 варианта.
8. **Конец и «Сыграть ещё».** Первый на Финише — победитель. Тем же составом можно сыграть сразу, тема разыгрывается заново; истории партии нет.

**Особые случаи.** Опоздавший после старта получает `party-already-started`, зрителя нет. Отвалившийся через 30 с получает автопилота — кубик / первая развилка / первый по цене вариант (`room/autopilot.ts:6`), видно в ленте. Отклонённый ход (`applyMove`) состояние не меняет, причина — только в серверный лог. Ушедший неотличим от отвалившегося, автопилот может довести его до победы; партия удаляется без подключённых и 5 мин без них (`room/cleanup.ts:9`), срок не перевзводится. Сбой при старте (`8fa7ab1`+`e49fd68`) не роняет сервер: не дошедшая до игры партия откатывается в лобби (`Party.abortStart()`) со строкой `lucid.ribbon.startFailed`, уже идущая — только лог (5.6, 10).

## 3. Правила и механика

### Роль игрока
Каждому игроку может достаться роль в мире партии — 2–5 слов в духе темы, «Ваня — хранитель чайника» (генерация — 4.3, хранение и путь к клиенту — 5.5). Чисто косметическая подпись рядом с ником (6.3): на атомы, цели и Условия не влияет, движок её не читает. Роль есть не всегда — модель могла прислать не на всех игроков или не прислать вовсе (4.4), тогда часть или все играют без роли, без падения.

### Трек, развилки, ход и кубик
Трек — граф без циклов от `startId` к `finishId` (`shared/track.ts:10-11`, `core/track.ts:26-109`). Развилка — клетка с `next.length>1`, ветки `FORK_BRANCH_LENGTH=2` сходятся обратно.

`ROLL` — кубик 1–6; дойдя до развилки раньше конца шагов, движение ждёт `CHOOSE_BRANCH`, остаток донашивается после (`core/movement.ts:27-52`). Атом `MOVE` развилку не спрашивает, берёт первую ветку — может двигать не того, чей ход.

Событие открывается только движением от своего хода (`reducer.ts:56-79`); движение эффектом Выбора новый ивент не открывает.

### События, цена, ресурс
Клетка `EVENT` — до 3 вариантов (`generation/schema.ts:59`): гарантированный (`cost`) или рискованный (`threshold`). Не по карману — ход отклонён; иначе Ресурс списывается, `threshold` — отдельным броском (`core/options.ts:7-45`).

Ресурс — один счётчик, старт `START_RESOURCE=3` (`core/setup.ts:6`), не ниже нуля — Долг. Ни один вариант не по карману — событие пропускается.

### Эффекты: атомы и цели

| Атом | Действие (value) |
|---|---|
| `MOVE` | сдвиг по треку, −4…4 |
| `RESOURCE` | изменить Ресурс, не ниже 0, −3…3 |
| `SKIP_TURN` | пропуски хода, 1…2 |
| `SWAP_WITH_FIRST` | обмен местами с лидером |

Атомы и диапазоны — `core/atoms.ts:27-60`, `generation/schema.ts:7-11`.

| Цель | Кто |
|---|---|
| `SELF` | сам игрок |
| `FIRST` | ближе к финишу, ничья — никто |
| `LAST` | дальше от финиша, ничья — никто |
| `ALL` | все игроки |

Цели — `core/targets.ts:5-30`. «На выбранного игроком» (CONTEXT.md, глоссарий) — не реализовано: нет в `ETarget`, ADR-0003 такую цель тоже не описывает.

Условие: поле `POSITION`/`RESOURCE`, оператор `EQ/GT/GTE/LT/LTE`, значение 0…20, один уровень, `otherwise` необязателен (`shared/effect.ts:26-50`). Атомы исполняются подряд; условие не прошло — срабатывает `otherwise` (`core/effects.ts:6-15`).

### Победа, перекос в пользу отстающих, пропуск хода
Победа — первый на `finishId`, проверка после броска, довыбора развилки и Выбора (`reducer.ts:36-48`).

Перекос в пользу отстающих — не код, а просьба в промпте «Наполнения»: чаще мешать первому, помогать последнему (`generation/prompt.ts:95-96`); результат код не проверяет. Перенести в код — открытый вопрос, решено оставить и мерить (`docs/lucid/OPEN-QUESTIONS.md`, «"Скелет кодом" не сделан»).

Пропуск хода — счётчик `skipTurns`, тратится вместо броска по одному, не уходит в минус.

### Числовые параметры

| Параметр | Значение | Где в коде |
|---|---|---|
| Игроков в партии | 2–6 | `room/Party.ts:10-11` |
| Стартовый Ресурс | 3 | `core/setup.ts:6` |
| Длина трека | 60−min(max(N,2),6)×5 (50 на двоих, 30 на шестерых) | `core/track.ts:16-18` |
| Развилки / длина ветки | 3–5 / 2 клетки | `track.ts:5-6,8` |
| Кубик | 1–6 | `core/random.ts:49-51` |
| Порог кубика / цена варианта | 2–6 / 1–3 Ресурса | `schema.ts:14,15` |
| Атомов в эффекте / вариантов на событие | 1–3 / 0–3 | `schema.ts:42,44,59` |
| Текст: заголовок/событие/вариант | ≤80/≤400/≤160 символов | `schema.ts:57,58,48` |
| Автопилот / удаление / потолок генерации | 30 000 / 300 000 / 180 000 мс | `autopilot.ts:6`, `cleanup.ts:9`, `init.ts:24` |

### Карточный слой (отложен)

| Элемент | Статус |
|---|---|
| Карта руки (≤3), Лавка, выложенная/двусторонняя карта | Не реализовано — ни типов, ни кода |
| Долг (Ресурс не уходит в минус) | Реализовано — поведение атома `RESOURCE` |
| Порядок игроков (первый/последний) | Реализовано — целями `FIRST`/`LAST` |
| Порядок срабатывания (клетка → карты по выбору) | Клетка реализована, событие только при ходе вперёд; карты — не реализовано |

## 4. Генерация партии

### 4.1 Кто что решает

ADR-0001: модель отвечает за контент, движок — за механику и структуру.

| Решает модель | Решает движок |
|---|---|
| Имя мира, ресурса, палитра, `mood` | Граф трека: развилки, схождение, длина (`core/track.ts`) |
| Названия/цвета регионов (3–5) | Разбивка клеток по регионам — по глубине пути |
| Роль игрока по нику, 2–5 слов (3) | Сопоставление ник→playerId, запасной партии ролей нет (`core/setup.ts:14-19,44`) |
| Заголовок, текст события и вариантов | Набор атомов/целей и диапазоны значений (`generation/schema.ts`) |
| Атомы эффекта в диапазоне | Валидация, ретраи, бюджет, откат на запасную |
| `threshold`/`cost` варианта | Персистентность, стадийная трансляция, учёт usage |

Клетка скрыта до посещения (`shared/content.ts:12-14`); регионы по глубине пути считает клиент, не сервер (`regionForDepth`, `client/src/lib/lucid/regions.ts:28-40` — 6.4).

### 4.2 Стадии и порядок

Двухстадийна: «Мир», затем события. `CONTEXT.md`/ADR-0004 описывают три стадии с отдельным «Скелетом» — устарело, решено 2026-09-23 (`docs/lucid/OPEN-QUESTIONS.md`, «Генерация остаётся двухстадийной»).

| Стадия | Кто строит | Клиентам |
|---|---|---|
| «Мир» | Модель, один вызов | Сразу по готовности (`init.ts:135-138`) |
| Скелет трека | Код, детерминированно, внутри «Наполнения» | Не транслируется отдельно |
| «Наполнение» (события) | Модель, пачками параллельно | Одним сообщением со скелетом (`init.ts:142-151`) |

Трек строится дважды сидом `${uuid}:track` (`room/Party.ts:195-200`) — детерминированно. Фаза `GENERATING` даёт клиенту `theme` без `state`. На `:nitro` полная партия собирается за 49–134 с, медиана 58 с (замер — 4.6).

### 4.3 Промпты

`buildWorldPrompt(theme, nicknames)` (`generation/prompt.ts:53-82`) просит `name`, `resourceName`, `palette`, `mood`, `regions` (3–5) и `roles` — пару `nickname`/`role` на каждое имя из списка выше, роль 2–5 слов в духе темы. Персонажи в честь игроков (обещаны `CONTEXT.md`, ADR-0001/0004) реализованы этой ролью, не полноценным именованным персонажем (`docs/lucid/OPEN-QUESTIONS.md`, «Персонажи в честь игроков», решено — вариант А).

`buildEventsPrompt(themeName, resourceName, cellIds, roles)` (`prompt.ts:84-124`) — по событию на номер из `cellIds`, регионы не передаются, роли — контекстом через `describeRoles` (`prompt.ts:41-51`): абзац с оговоркой, что событие может выпасть любому игроку, а не только тому, чья это роль; без ролей абзац не добавляется. У трети событий один вариант платный. Диапазоны `value` — из `ATOM_RANGES`. `condition`/`otherwise` схема допускает, промпт не объясняет — модель их не присылает. Язык — русский по языку промпта, явной инструкции нет.

### 4.4 Схемы

Валидация — zod, `z.strictObject`. `z.toJSONSchema` (`generation/model.ts:44`) → `responseFormat: json_schema`, маршрутизация сужена `provider.requireParameters`. Провайдер гарантирует форму ответа, не диапазоны — их ловит своя валидация (`schema.ts:6-84`):

| Поле | Значение |
|---|---|
| `MOVE` / `RESOURCE` / `SKIP_TURN` / `SWAP_WITH_FIRST` | −4…4 / −3…3 / 1…2 / 0 |
| `threshold` / `cost` | 2…6 / 1…3 |
| регионов / имя региона | 3…5 / ≤24 знаков |
| роль игрока / ник в паре роли | ≤50 / ≤60 знаков, весь список необязателен (`schema.ts:80-86`) |
| палитра | 3…6 цветов `#rrggbb` |
| текст / заголовок / вариант | ≤400 / ≤80 / ≤160 |
| атомов в эффекте / вариантов в событии | 1…3 / ≤3 |

Номера клеток схема не проверяет — сверяет `generation/pipeline.ts` (4.6).

### 4.5 Модель и провайдер

OpenRouter. `DEFAULT_MODEL` — `deepseek/deepseek-v4.1-flash:nitro` (`generation/model.ts:22`, заказчик выбрал 2026-09-22, в коде с `aae7a0e`), переопределяется `LUCID_MODEL` из `server/.env` (`model.ts:42`). Ключ — `OPENROUTER_API_KEY` (`model.ts:33`). Сравнение моделей и обоснование — `docs/lucid/MODELS.md`.

### 4.6 Скорость

Пачки `EVENTS_CHUNK_SIZE=6` параллельно; бюджет `GENERATION_BUDGET_MS=180_000` (3 мин, `init.ts:24`, снижено с 7 `aae7a0e` — перекрывает худший замер партии примерно в 1.25 раза и не держит игроков у экрана при зависшем запросе), общий `AbortController` рвёт всё по дедлайну; `MAX_ATTEMPTS=3` на запрос.

| Замер | Мир | Кусок (6 событий) | Партия |
|---|---|---|---|
| `:nitro` / без nitro, одиночные запросы | 4.5 с / — | 10–27 с / 12–307 с | $0.004–0.009 за кусок / ~6 мин партия, `sort:'throughput'` хуже |
| `:nitro`, до правки промпта (3×3 игрока, 43 события) | 11–23 с | — | 80/115/145 с; $0.050–0.065; запасных 0; платных 15/43 |
| `:nitro`, после правки (`8dc9ce2`, 3 темы, 43 события, 2026-09-23) | 4.5–53.5 с | — | 49/58/134 с, медиана 58; $0.037–0.055; запасных 0 из 54 вызовов; платных 15/43 |
| `mistral-small-3.2-24b` | — | — | 76 с; контент хуже — шаблонные события, платный вариант у всех |

Баг найден и закрыт (`8dc9ce2`): хвостовой кусок из одной клетки содержал «...для каждой из клеток: 43», модель читала это как число событий партии, а не клеток куска, и генерировала лишнее — самый дорогой и часто самый медленный вызов. Промпт теперь называет число событий партии отдельной фразой. Полный разбор — `docs/lucid/MODELS.md`.

### 4.7 Запасная партия

Срабатывает при провале «Мира» или куска «Наполнения» в бюджете — вся партия на запасную, миры не смешиваются; то же при исключении.

`generation/fallbackContent.json`: 4 региона, 48 событий — ровно клеток-событий на треке для двоих. `loadFallbackContent` тасует пул от `${seed}:fallback`. Схема (4.4) в рантайме не накладывается — проверяет только тест `fallback.test.ts:18-33`.

Честность: строка «Придумать ваш мир не получилось, играем на запасном» при `usedFallback`, от игры, остаётся в ленте.

### 4.8 Учёт токенов и стоимости

Таблица `usage`: `party_uuid`, `input_tokens`, `output_tokens`, `cost_usd`, `used_fallback`, `created_at` (`storage/db.ts:32-40`).

Подключено (`de93753`): `PartyGroup.save`→`takeUsage()`→`saveUsage`, раз на генерацию; токены неразобравшегося ответа учитываются, кусков-опоздавших из `Promise.all` — нет, сознательно (`OPEN-QUESTIONS.md`).

В работе, решение заказчика («Полный учёт трат и отчёт командой», `OPEN-QUESTIONS.md`): построчно на каждый вызов (партия, стадия, модель, токены, стоимость, время, успех) плюс итог с метриками содержания и команда `yarn workspace @trgames/server lucid:usage`.

### 4.9 Палитра и оформление от модели

От модели — только `palette`, `mood` и цвета регионов, без гарантий контраста. Читаемость поверх сгенерированной палитры гарантирует клиент — раздел 6.

## 5. Сервер: устройство и протокол

### 5.1 Карта модулей

| Путь | За что отвечает |
|---|---|
| `server/src/index.ts` | Точка входа: `.env`, общий `socket.io Server`, CORS, `connectionStateRecovery`, порт |
| `init.ts` (экспорт из `index.ts` как `Lucid.init`) | Неймспейсы `/lucid`, `/lucid/lobby`, обработчики событий, рассылка, автопилот, удаление партий |
| `core/**` | Движок: атомы, эффекты, цели, перемещение, редьюсер ходов, сборка состояния, `formatForPlayer` |
| `generation/**` | Генерация партии через OpenRouter — раздел 4 |
| `room/**` | `Party.ts` (одна партия), `PartyGroup.ts` (набор + хранилище), `autopilot.ts`, `cleanup.ts` |
| `storage/**` | `db.ts` — `node:sqlite`; `index.ts` — реэкспорт |
| `i18n/translations/ru.ts`, `vitest/factories.ts`, `*.test.ts` | Тексты ошибок/ленты; тестовые фабрики; тесты рядом с модулями |

`room/**` и `storage/**` не общие с `games/cryptoz` — платформенный слой TRGames пока декларативен (ADR-0007).

### 5.2 Модель движка

Чистые функции над `G` (данные партии) и `ctx` (фаза, очередь). Единственный вход — `applyMove` (`core/reducer.ts`): сверяет `stateId`, фазу и что ходит `ctx.currentPlayer`; при несовпадении отдаёт то же состояние без объяснения.

Сидированный ГПСЧ (mulberry32) — `{seed}` в `G.random`; трек и кубик — разные потоки. Архитектура — ADR-0002 (сервер авторитетен), ADR-0006 (без игрового движка), ADR-0007 (встроена в TRGames второй игрой); обоснования — раздел 9.

### 5.3 Транспорт

Два неймспейса на `io`: `/lucid/lobby` — только `create-party`, короткоживущий; `/lucid` — партия целиком, рукопожатие несёт `partyId`/`playerId`/`nickname`, `namespace.use` находит партию, `party.join()` — отказ как `connect_error`.

Комнаты: `<partyId>` — все соединения партии, общая лента (`append-ribbon`); `player:<partyId>:<playerId>` — соединения игрока, личный вид (`update-party`) и ошибки (`show-error`).

Личная комната несёт `partyId` (фикс `18bfe80`): раньше `player:<playerId>` была общей на весь неймспейс, вторая партия того же браузера получала чужую рассылку.

Комната на партию, не неймспейс — ADR-0008: `connectionStateRecovery` (30 с) восстанавливает комнаты сокета; неудача восстановления — просто полная пересылка вида (клиент не ходит оптимистично). CORS — раздел 8.

### 5.4 Протокол

**Клиент → сервер**

| Событие | Payload | Проверки | Что делает |
|---|---|---|---|
| `create-party` (`/lucid/lobby`) | — (колбэк) | `playerId` из query | `group.create`, персист, таймер удаления; колбэк `partyId`/ошибка |
| `propose-theme` | `theme: string` | `LOBBY`, участник, ≤200 симв. | сохраняет предложение, `hasAnswered = true` |
| `decline-theme` | — | те же | очищает предложение, `hasAnswered = true` |
| `start-party` | — | `ownerId`, `canStart` (≥2 игрока) | генерация (4, бюджет 180 000 мс), досрочно «Мир», `setupParty` → `PLAYING` |
| `make-move` | `TMove` (`ROLL`/`CHOOSE_BRANCH`/`CHOOSE_OPTION`) | `stateId`/фаза/очередь — в `applyMove` | применяет ход; отказ — то же состояние, причина в `console.warn` сервера |
| `play-again` | — | нет | новая партия тем же составом, `nextPartyId` у старой |

Обработчики — через `guard()`: успех → `persist`+`broadcast`; ошибка → `show-error` вызвавшему.

**Сервер → клиент**

| Событие | Payload | Кто получает |
|---|---|---|
| `update-party` | `TPartyView`: фаза, лобби, тема, `TStateForPlayer?`, `usedFallback`, `nextPartyId` | Лично каждый, `player:<partyId>:<playerId>`, на каждый `broadcast()` |
| `append-ribbon` | `string[]` — прирост журнала | Вся партия, `<partyId>`, только если прирост не пуст |
| `show-error` | `{ message: string }` | Только вызвавший, личная комната (в лобби — тот же сокет напрямую) |

«Партия не найдена» через `show-error` не идёт — бросается в middleware, приходит как `connect_error`.

### 5.5 Граница секретности

`core/formatForPlayer.ts` — явный список полей `G` (`Omit<TG, 'log' | 'random'>`): новое поле без упоминания здесь ломает сборку.

Уходит: `players`, `order`, `track`, `theme`, `visited`, `winner`, `branchChoices`, `pendingSteps`, `lastRoll`, посещённые `events`. Не уходит никогда: `G.random`, `G.log` целиком, непосещённые события.

Роль игрока — не секрет, отдельного поля в списке заводить не пришлось: сырые пары ник/роль от модели (`TPartyContent.roles`, `shared/content.ts:43-54`) `setupParty` сопоставляет с `playerId` по нику и пишет прямо в `TPlayer.role` (`shared/state.ts:16`, `core/setup.ts:14-19,44`) — а `TPlayer` целиком уже входит в `players` выше, так что роль едет до клиента бесплатно.

### 5.6 Жизнь партии

| Этап | Что происходит |
|---|---|
| Создание | `create-party` → `LOBBY`, персист и таймер удаления сразу |
| Вход | Только в `LOBBY` (иначе `party-already-started`); известный `playerId` — в любой фазе |
| Старт | Только `ownerId`, `canStart`; жеребьёвка темы, генерация, `setupParty` |
| Конец | `track.finishId` → `ENDED` внутри редьюсера |
| Обрыв/возвращение | `disconnect` гасит связь только при опустевшей личной комнате |
| Автопилот | Один на партию; `syncAutopilot()` заводит/снимает `AUTOPILOT_DELAY_MS=30000` на неподключённого `currentPlayer` |
| Удаление партии | `cleanup.sync()`: без подключённых — `CLEANUP_DELAY_MS=300000` (5 мин), повтор не перевзводит |
| Сыграть ещё | Новая партия тем же составом; `nextPartyId` у старой |
| Рестарт сервера | `group.get()` при промахе поднимает `TPartySnapshot` из базы, участники отключены принудительно |

Старт партии (`8fa7ab1`+`e49fd68`): `.catch` на `party.start(...)` в `init.ts` ловит то, что раньше улетало необработанным отказом промиса и роняло весь процесс вместе с Cryptoz. Партия, не дошедшая до `PLAYING`, откатывается `Party.abortStart()` — фаза обратно в `LOBBY`, тема, `usedFallback` и `state` сброшены — и получает строку `lucid.ribbon.startFailed`; партия, уже идущая, — только запись в лог. `PartyGroup.save` не пишет партию, которой уже нет в группе, — защита от воскрешения удалённой партии из базы.

### 5.7 Хранение

`node:sqlite`, путь `LUCID_DB_PATH ?? 'lucid.db'`, обобщено по типу документа (`createStorage<TDocument>`).

| Таблица | Поля |
|---|---|
| `parties` | `uuid TEXT PRIMARY KEY`, `theme TEXT NOT NULL`, `state TEXT NOT NULL`, `updated_at INTEGER NOT NULL` |
| `usage` | `id INTEGER PRIMARY KEY AUTOINCREMENT`, `party_uuid`, `input_tokens`, `output_tokens`, `cost_usd`, `used_fallback`, `created_at` |

`state` — `TPartySnapshot` целиком в JSON (секретов нет — `G.random`/`G.log` внутри). `theme`-колонка дублирует `snapshot.theme?.name` — шов модерации, ADR-0005.

Пишется на ход, после генерации, на соединение, в `play-again`. Читается только при промахе `PartyGroup.get()`. Удаляется только из `cleanup` по отсрочке (5.6), не опустевшие не подчищаются — решено не удалять, пока не станет заметно. `usage` — раздел 4.8.

Сгенерированный контент — отдельный источник дефектов: всё, что приходит от нейросети, проверяется своей схемой и сверяется с реальным треком. Тестовый прогон и боевой запуск резолвят модули по-разному: `fallback.json` рядом с `fallback.ts` заставлял `ts-node` в бою грузить json раньше ts, сервер падал на сорванной генерации при всех 196 зелёных файлах тестов — модуль не должен иметь соседа с тем же именем и другим расширением. Грабли окружения: не держать `cd` (ломает `fnm`); Windows оставляет живые `node` после `TaskStop`/`/exit` — гасить по PID; `eslint .` в `server/` падает вне `src`; один пишущий агент на дерево одновременно.

| Файл | Переменная | Назначение |
|---|---|---|
| `server/.env` | `OPENROUTER_API_KEY` | ключ OpenRouter; при отсутствии — пустая строка |
| `server/.env` | `LUCID_MODEL` | модель генерации; при отсутствии — `DEFAULT_MODEL` из кода |

Скрипты вне `server/src` — с `TS_NODE_COMPILER_OPTIONS='{"module":"commonjs","moduleResolution":"node"}'`, иначе `ts-node` резолвит модули иначе, чем основной процесс.
