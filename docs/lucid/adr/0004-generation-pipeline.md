# 4. Генерация пайплайном, скелет карты строится кодом

Дата: 2026-09-21

## Статус

Принято

## Контекст

Весь контент партии генерируется до её старта (см. CONTEXT.md, «Генерация
партии»). Оставалось решить, делается ли это одним вызовом модели или
несколькими.

Один вызов означает ответ, содержащий сорок клеток, три десятка карт,
персонажей и тему разом. На таких объёмах модели теряют согласованность к
концу ответа, нарушают схему и упираются в лимит вывода. Главное же —
при провале валидации из-за одной кривой карты выбрасывается вся генерация.

Отдельный вопрос — кто строит граф трека. У графа есть жёсткие требования:
отсутствие циклов, схождение веток, достижимость Финиша, длина в заданных
пределах.

## Решение

Генерация разбита на стадии, и режутся они по границам согласованности, а не
по типам контента:

1. «Мир» — один маленький вызов: тема, оформление, персонажи, тон.
2. «Скелет» — строится кодом: граф трека и раскладка типов клеток.
3. «Наполнение» — события и карты пачками параллельно, с «Миром» в контексте.

Граф трека нейросеть не генерирует вовсе.

## Последствия

Решающая выгода — гранулярность повтора: перегенерируется только сломавшаяся
пачка, а не вся партия. Стадия 3 параллелится, поэтому по времени пайплайн
не проигрывает одному большому вызову, а обычно выигрывает.

Скелет, построенный кодом, — это тридцать строк с абсолютной гарантией
вместо бесконечного потока невалидных графов от модели, которые пришлось бы
ловить валидатором и перегенеривать. Заодно процедурная форма трека и есть
основной источник визуальной уникальности партии.

Пайплайн не противоречит запрету на догенерацию по ходу партии: все стадии
выполняются до старта, внутри прелоадера.
