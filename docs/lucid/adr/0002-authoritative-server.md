# 2. Авторитарный сервер вместо P2P

Дата: 2026-09-21

## Статус

Принято

## Контекст

Игра рассчитана на компанию друзей, а не на публичные лобби с незнакомцами.
Обычный аргумент за авторитарный сервер — защита от читеров — здесь слабый:
жульничать в дружеской партии желающих мало, а хостинг стоит денег.

Есть и более дешёвая схема: один из игроков хостит партию, остальные
подключаются к нему.

## Решение

Партия целиком живёт на сервере. Клиент отправляет только намерения
(«бросаю кубик», «выбираю второй вариант») и получает в ответ новое состояние.
Сервер бросает кубик, применяет эффекты и решает, что каждый игрок видит.

## Последствия

Решающая причина не читерство, а спойлеры. Весь контент партии генерируется
на старте одним ответом модели. При хост-клиентной схеме этот ответ целиком
оказывается на машине хоста, и хост видит содержимое всех клеток впереди —
достаточно открыть инструменты разработчика. Игра, где один участник заранее
знает карту, сломана даже без злого умысла.

Клиенту отдаётся только уже открытое содержимое. Непройденные клетки
приезжают как заглушки.

Побочная выгода: партия переживает выход любого игрока, включая того, кто её
создал. При хост-клиентной схеме уход хоста убивал бы партию.

Цена: нужен постоянно работающий сервер и оплата его хостинга.
