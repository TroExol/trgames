# Модели генерации: сравнение и выбор

## Зачем

На кнопке лобби заказчику обещали «около полутора минут», а на практике
партия на `deepseek/deepseek-v4.1-flash` собиралась около шести. Узкое место —
не сама модель, а разброс эндпоинтов OpenRouter: один и тот же кусок генерации
шёл от 12 до 307 секунд. `provider.sort: throughput` сделал только хуже —
257 с против 91 без сортировки.

## Замер 1, одиночные запросы (2026-09-22)

Настоящие промпты и схемы, тема «чайная церемония у драконов». На модель — один
запрос мира и три запроса куска из 6 событий, строго по очереди (без
параллелизма, чтобы запросы не мешали замерам друг друга).

| Модель | Мир | Куски событий | $ за кусок | Итог |
|---|---|---|---|---|
| `deepseek/deepseek-v4.1-flash` | 26.6 с | 75.1 / 76.2 / 112.2 с | 0.0034 / 0.0006 / 0.0008 | ок |
| `deepseek/deepseek-v4.1-flash:nitro` | 4.5 с | 27.0 / 10.5 / 13.8 с | 0.0086 / 0.0040 / 0.0060 | ок |
| `mistralai/mistral-small-3.2-24b-instruct` | 8.3 с | 63.6 / 48.9 / 42.6 с | ~0.0003 | один кусок из трёх не прошёл схему |
| `openai/gpt-oss-120b` | 32.7 с | упали за 0.1 с | — | мир ок, события — `ResponseValidationError` |
| `z-ai/glm-5.3-flash`, `qwen/qwen3.5-flash-02-23`, `xiaomi/mimo-v2.6-flash`, `bytedance-seed/seed-1.6-flash` | упали за 0.1 с | упали за 0.1 с | — | `ResponseValidationError` из SDK |

Mistral отдельно проверен на живой партии: 76 секунд на партию целиком, но
содержание хуже — все события по одному шаблону, платный вариант выпал у 48
событий из 48 вместо трети, палитра кислотная, из именованных цветов CSS.

Пять моделей упали ещё на уровне API, до нашей схемы — `ResponseValidationError`
из SDK. Причину не разбирали: выбор к этому моменту уже был сделан. Разобрать,
если понадобится запасная модель.

## Замер 2, полный пайплайн на nitro (2026-09-23)

Настоящий `generateContent`, 3 игрока, 43 события, 3 темы.

| Тема | До правки промпта | После правки (`8dc9ce2`) |
|---|---|---|
| чайная церемония у драконов | 115.4 с, $0.064 | 134.5 с, $0.055 (мир 53.5 с — выброс эндпоинта) |
| пираты в пустыне | 145.0 с, $0.065 | 58.0 с, $0.040 |
| киберпанк-библиотека | 79.6 с, $0.050 | 48.9 с, $0.037 |

Медиана: 115 → 58 с. Запасных партий и ошибок — 0 из 54 вызовов. Платный
вариант выпал у 15 событий из 43 (цель — треть).

Правка промпта (`8dc9ce2`): хвостовой кусок из одной клетки содержал фразу
«для каждой из клеток: 43» — про число клеток именно в этом куске, а не про
число событий в партии, но модель читала это «43» как число событий и
генерировала кусок соответствующего размера. Теперь промпт называет число
событий партии отдельной фразой, не завязанной на число клеток в куске.

## Замер 3, рассуждение и его выключение (2026-09-23)

Партии всё равно уходили на запасной контент, хотя медиана из замера 2 (58 с)
укладывалась в бюджет 180 с. По замеру токенов у `deepseek/deepseek-v4.1-flash:nitro`
рассуждение (reasoning) включено по умолчанию, и у него нет отдельного
переключателя «выключить», только уровень `effort` — модель рассуждает
даже без явного запроса. На кусок из 6 событий рассуждение занимало ~85%
выхода: около 10 000 токенов из ~11-12 тысяч, против 1-2 тысяч без него.
Генерация укладывалась в бюджет по медиане, но реальный разброс эндпоинтов
`:nitro` регулярно выбивал отдельные куски за 180 с, и партия целиком уходила
на запасной контент.

SDK (`@openrouter/sdk`, тип `ChatRequestReasoning`) не даёт поля
«включено/выключено» — только `effort`, значения вплоть до `'none'`.
Реальным запросом через `generateJson` (буквально `buildEventsPrompt` +
`eventBatchSchema` из репозитория) подтверждено: `reasoning: { effort: 'none' }`
у `deepseek/deepseek-v4.1-flash:nitro` принимается без ошибки, и
`response.usage.completionTokensDetails.reasoningTokens === 0` — рассуждение
выключается полностью, а не просто урезается. Пример вызова —
`server/src/games/lucid/generation/model.ts`, поле `reasoning` в `chatRequest`.

Полный пайплайн «как в игре» (мир, затем 8 кусков по 6 событий параллельно,
48 событий, 2 игрока, тема «пираты в пустыне»), время — после полного чтения
тела ответа (ловушка ниже), 3 прогона на конфигурацию:

| Конфигурация | Мир | Медиана / максимум куска | Партия целиком | Ошибки | $ за партию | out / reasoning токенов на кусок |
|---|---|---|---|---|---|---|
| `deepseek/deepseek-v4.1-flash:nitro`, reasoning off | 2.4–2.7 с | 10.0–12.1 с / 10.5–14.1 с | **13.2–16.8 с** | 0 из 24 кусков | $0.016–0.017 | ~1200–1680 / 0 |
| `deepseek/deepseek-v4.1-flash` без nitro, reasoning off | 5.2–8.1 с | 11.5–41.3 с / 38.8–51.2 с | 55.4–185.3 с | 2 таймаута (180 с) из 24 кусков, оба в одном прогоне | $0.009–0.012 | ~1250–2280 / 0 |
| `z-ai/glm-5.3-flash`, effort minimal (у него reasoning не выключается) | 7.3 с | 16.0 с / 89.0 с | 96.3 с | 0 из 8 кусков, 1 выброс на 89 с | $0.0055 | ~1000–1330 / 0–9 |

Запасного контента ни в одном прогоне не было. Сырые события одного прогона
каждой конфигурации — `bench/out/stage2/config-{a,b,c}-*/` (не в репозитории,
в скретчпаде замера), для проверки качества текста и баланса.

Правка промпта (`buildEventsPrompt`, тот же коммит): абзац про баланс
вариантов переписан короткими пунктами вместо сплошного текста, добавлена
явная оговорка не считать вероятности и не перепроверять каждое событие
цифрами — рассуждение выключено, а без него модель не должна тратить
токены на то, что раньше делала в скрытом слое рассуждения. В JSON-пример
добавлен третий, бесплатный гарантированный вариант (без `cost` и
`threshold`) — раньше пример показывал только платный и рискованный, хотя
схема и так допускает третий любой. `SWAP_WITH_FIRST` в `describeAtoms`
теперь явно говорит «target всегда SELF, value всегда 0» — раньше про
`target` не было сказано вовсе.

**Вывод.** `:nitro` при выключенном рассуждении на голову быстрее и
устойчивее: 13–17 с на партию из 48 событий против 55 с и выше (с
таймаутами) без `:nitro`. Корень прежних уходов на запасной контент — не
разброс эндпоинтов сам по себе, а рассуждение, съедавшее бюджет по кускам
задолго до среднего. `z-ai/glm-5.3-flash` рабочий вариант на крайний
случай (reasoning не выключить, но effort minimal почти не мешает), но
медленнее и с выбросами — не замена `:nitro`, а резерв.

## Решение

`deepseek/deepseek-v4.1-flash:nitro` с `reasoning: { effort: 'none' }` —
выбор модели подтверждён заказчиком 2026-09-22, рассуждение выключено по
итогам замера 3 (2026-09-23). Около $0.016–0.017 за партию из 48 событий
(было $0.04–0.065 с рассуждением на партию из 43). Потолок ожидания — 3
минуты (`GENERATION_BUDGET_MS` в `server/src/games/lucid/init.ts`), на
кнопке — «одну-две минуты», с большим запасом при новой скорости.

Сменить модель — через `LUCID_MODEL` в `server/.env`, код трогать не нужно.
Рассуждение выключено в коде (`generation/model.ts`), не переменной
окружения — оно не специфично для модели так, как её id.

## Как перемерить

Скрипт замера в репозиторий не входит. Мерить обёрткой поверх `generateJson`
(`server/src/games/lucid/generation/model.ts`) вокруг вызовов `generateContent`.
Статистика реальных партий — в учёте трат (раздел 4.8 `PRD.md`).

Ловушка: OpenRouter отдаёт HTTP-заголовки сразу и держит соединение открытым
до конца генерации — если засечь время по приходу `fetch()` (или до чтения
тела ответа), получится не настоящее время генерации, а время до первого
байта. Время нужно снимать после `await res.text()` (или `response.text()`),
а не раньше.
